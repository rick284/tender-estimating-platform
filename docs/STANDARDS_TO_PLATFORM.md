# How Rick's governing standards become platform requirements

Source documents are in `docs/standards/` (Rick's own documents; keep this repo private). This file OVERRIDES `docs/SPEC.md` wherever they differ. Platform = the standards made executable and enforced; the AI works inside them.

## A. Corrections to SPEC v0.1
1. **"Triple verification" is not the blind re-estimate.** In the Triple Verification Standard Rev4 it means the THREE CHECKS REQUIRED FOR GREEN: (1) primary/current evidence, (2) independent check, (3) first-principles check (quantity, productivity, unit conversion, waste, crew/plant, scope, arithmetic, cost chain, programme reconciliation). Applies per rate/quantity/productivity/weather factor/allowance. The workbook's Rate Verification sheet implements it (Evidence 1/2/3, results, score, status). The blind "fresh chat, no numbers" run Rick describes is most likely the **Independent Estimate Review Board** process (Rev4.1 workbook has the tabs). Keep both modules; rename the blind run "Independent Review Board"; CONFIRM with Rick and obtain the Review Board standard/prompts.
2. **Management Reserve is not rate x base by default.** There is NO default %. It is a commercial adjudication provision, selected after reviewing quantified sensitivities, weighted exposures, unquantified tails, overlap, maturity, RED count, risk transfer, confidence; frozen as a FIXED AMOUNT per estimate revision; never auto-grows; never auto-consumed when a RED resolves (price the real consequence in the right place, remove superseded provisional treatment, update Risk Truth, reassess reserve, issue controlled revision). Not a programme cost. Hobsonville 4% ($18,269.06 on base $456,726.56) is a worked example only.
3. **Quantity status vocabulary** is MEASURED / PROVIDED / CALCULATED / ALLOWANCE-PC / QUOTED (replaces my SCHEDULE/MEASURE/ASSUMED labels). Every inserted number carries one. Measurement method (vector PDF, calibrated, schedule) is a separate field.
4. **Lifecycle vs verification are separate axes.** Lifecycle: WORKING -> REVIEW -> READY FOR RELEASE -> RELEASED/BASELINED -> CHANGE CONTROL/REOPENED -> CLOSED/ARCHIVED. Verification: GREEN/AMBER/RED. (SPEC "WORKING/TENDER-ISSUE/CONTRACT-AWARD HOLD" mixed them; Hobsonville "HOLD" is a release status driven by RED items.)
5. **Materials & Component Takeoff** is a coverage/procurement audit only, never a second cost chain; every permanent component ends in a declared treatment (Included / Owner TBC / By Others / Existing-Retain / Excluded / Reference Only / RFI Hold); unallocated components = release HOLD.
6. **Markups**: separate Internal Verification Markups and Client Issue Markups; each issued markup states "ESTIMATE MARKUP ONLY - NOT FOR CONSTRUCTION"; tied to estimate revision and source drawing revision; original source governs; discrepancies become RFIs. Each active QS item keeps original source reference + link, and Markup ID + link where applicable.

## B. Permanent workbook/library architecture rules (Master Prompt Rev5) -> data and engine rules
- One visible cost chain: Resource Rate Library -> Resource Build-Up -> QS Takeoff -> Tender Build-Up -> Summary -> Cashflow/Programme refs. Change once, flows everywhere; no hard-coded duplicates; derived fields read-only.
- Library cumulative; supersede with source/date/status; never delete history. Library update requires source, date, reviewer, change reason.
- Overhead and profit separate inputs; margin/markup/contingency/risk never interchangeable.
- Revision keeps document control, source versions, previous release totals for reconciliation.
- Risk Truth is the controlling risk layer: physical quantifiable consequences go back into Build-Up/QS; specialist engines (weather) stay in their path and are referenced not re-added; CA01 = design/scope residual only, CA02 = construction/execution residual only; no generic % contingency; positive provision needs Residual Distinct = Yes + one integration target.
- Risk calc modes: Already in Base/No Add, Unit Rate Delta, Probability x Impact, Scenario Weighted, Fixed Allowance, Specialist Engine, By Others/Excluded, RFI Hold. Per risk: ID, description, class, source/evidence, owner, RFI/closeout, baseline + where it sits, outside-baseline trigger, residual, affected driver, cost-treatment owner (Primary/Contributing/Reference Only), overlap group, embedded-variability check, evidence status, residual-distinct, integration target/complete, rerun trigger, actual outcome (kept separately).
- Release gate: RED risk count, RED exposure count, duplicate-cost status, programme/cost reconciliation, integration completeness. Any unexplained duplicate, broken cost path or unresolved material RED blocks final release (working/tender stage may carry disclosed AMBER/RED).
- Probability policy: 50/50 is not a default; weights need evidence; probability status GREEN/AMBER/RED-UNKNOWN; unknown probability = no expected value (keep as sensitivity); unknown impact = unquantified tail; mutually exclusive scenarios sum to 100%; correlated risks use overlap group/joint scenario/capped. Expected exposure uses delta against current priced baseline.
- Programme: working days vs productive crew days vs elapsed calendar days always distinct; productive labour/plant from resource hours; supervision/working-day prelims from site working days; weekly/monthly hire from elapsed time; mobilisation/one-offs not scaled by span; unexplained mismatch = RED release blocker; unknown start date -> stated working-day calendar, no date-specific holidays.
- Weather: per Master Prompt "Weather output rules" and Triple Verification weather section (NIWA 1991-2020 GREEN source; task factors AMBER until calibrated; local factor != 1.00 needs written basis; wind separate and AMBER proxy; critical path only; never double count with dewatering/contingency/prelims; rerun triggers; weather allowance is not EOT entitlement; post-award Weather Log feeds back under change control).
- Labour true-cost policy: library labour = true direct employer cost per productive hour (wage + employer on-costs [NZ: KiwiSaver, ACC levy; AU: super, workers comp, payroll tax] + paid non-productive time recovered over productive hours); evidence hierarchy company actual > reviewed historical > comparable contractor > market normalised (AMBER) > raw wage (not allowed -> RED); excludes overhead, profit, fleet, prelims; agency labour = quoted charge, no extra on-costs; library record fields listed in policy section 12; no silent overwrite of history; PAYE is not an employer cost.

## C. Process the platform must run
1. **Intake**: the 20-field Estimate Intake Block (job, location, client, type, package, purpose, level [Concept/Feasibility/Tender/Variation], pricing basis, contract type, done, programme constraints, site constraints, scope boundaries, documents, missing docs, locked assumptions, risks, interfaces, inclusions style, top-3 questions). Missing info -> RFI with impact, never a guess.
2. **Backend reference check** before pricing: record versions of intake, master prompt, triple-verification standard, rate library, productivity/crew library, weather tool, supplier quote register, programme model, commercial settings, Risk Truth + gate, materials takeoff coverage, source & markup register. Missing/obsolete -> numbered verification action.
3. **Pack output** (Master Prompt step 3): A Job Understanding; B Scope of Work; C Exclusions; D Assumptions; E Interfaces/By Others; F Risks; G RFIs (what's missing, where expected, why it matters, decision impact); H Takeoff & Quantity Schedule (QS code, unit, basis, source ref+link, classification, verification, owner, markup ID/link); I Materials & Component Takeoff; J Pricing Build-Up; K Programme & Sequencing; L Client Summary; M Plan/Source/Markup traceability map. Plus Plan & Document Register first.
4. **Conclusion & change control**: Definition of Done set early (objective, deliverables, DoD, materiality basis, approval authority, lifecycle state); 30-point estimate DoD; materiality/diminishing-return stop test; precision ceiling; READY FOR RELEASE recommendation wording; RELEASED baselines immutable; post-release questions are discussion only ("BASELINE UNCHANGED"); changes only via explicit CR-n (baseline, change, reason, scope/qty/resource/programme/weather/risk/commercial impact, verification, decision, new revision); post-conclusion ideas -> backlog (ENH/DEF/CR/RFI/VER/NEW WS); closure record (20 fields). AI duty: recommend conclusion; do not expand scope or reopen settled decisions.
5. **Knowledge loop**: Knowledge Bank -> Estimate -> Verification/New Evidence -> Knowledge Bank; after construction Actual -> Variance -> Cause -> Reviewed Actual -> Bank. Before researching externally, search the Bank. Every material verified rate (GREEN/AMBER/RED) is LOGGED back; LOG != PROMOTE; statuses reusable / project-specific / historical / superseded / challenge-only; never average unlike rates; productivity returned only with context (crew, plant, hours, conditions, etc); quote return with normalised basis and inclusions/exclusions; Knowledge Return Check (10 questions) before workstream closes; actuals never overwrite tender assumptions; commercially sensitive data kept private with sanitised central record. The Bank is currently a Google Sheet "3Bears Construction Intelligence Register" (id 1ummWFxW0EHctJOENT3nu4jHTnGp_UOoZ6FF5uSxqJKk) — read its schema before designing the Bank tables; ONE bank, no competing per-job databases.
6. **Reference library (SK6, AACE)**: reference-only; no example numbers imported into rates/productivity; adoption path: already covered / reference only / candidate for testing / accepted via change control / not suitable.
